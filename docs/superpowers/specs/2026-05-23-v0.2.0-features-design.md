# Design: sqdist v0.2.0 features

Date: 2026-05-23
Status: Approved
Component: `sqdist` (src/main.rs, plus new build.rs)

## Summary

Five user-facing additions plus a version bump to **0.2.0**:

1. Batch modes (`--list`, `--stdin`) with `-t` exit non-zero when zero rows match.
2. `-v`/`--version` prints `sqdist <version> (<short-git-sha>)` and exits.
3. Help text gains a one-line explanation of each output field.
4. `--fields <comma-list>` restricts output to specific fields (all modes).
5. Single-pair human output gains a `[CATEGORY] sentence` interpretation verdict.

No new runtime dependencies. One new build-time file (`build.rs`). Breaking
changes are acceptable (pre-1.0, single owner), but none are required here —
all additions are backward-compatible except the exit-code change (#1), which
is the explicitly requested behavior change.

## Feature 1 — Batch-mode exit codes with `-t`

Today `--list`/`--stdin` always exit 0. Change: when `-t <threshold>` is given,
both batch modes track whether **any** row passed the threshold (i.e. was
emitted as an alert):

- ≥1 alert emitted → exit `0` (`SUCCESS`)
- zero alerts → exit `1` (`FAILURE`)

Without `-t`, batch modes still always exit `0` (no pass/fail notion). This
mirrors single-pair `-t` semantics. Usage/IO errors remain exit `2`.

Implementation note: the streaming `--list` path and the `--stdin` path each
need a `matched: bool` (or a count) that flips true on each emitted row; return
the right `ExitCode` after the loop. The buffered `--list --sort/--top` path
checks whether the results vec is non-empty.

Final exit-code table after this change:

| Code | When |
|---|---|
| 0 | `--help`/`--version`; single-pair without `-t`; single-pair `-t` with distance ≤ t; batch without `-t`; batch `-t` with ≥1 alert |
| 1 | single-pair `-t` with distance > t; batch `-t` with zero alerts |
| 2 | usage error (bad args, mode conflict, invalid `--fields`/`--metric`/`--len-tolerance`); `--list` file open failure |

## Feature 2 — `-v` / `--version`

A `build.rs` runs `git rev-parse --short HEAD` at compile time and emits the
SHA as a compile env var (e.g. via `println!("cargo:rustc-env=SQDIST_GIT_SHA=…")`).
If git is unavailable or the command fails (e.g. crates.io builds from the
packaged tarball, which has no `.git`), the SHA falls back to `unknown`.

`--version`/`-v` prints `sqdist <CARGO_PKG_VERSION> (<sha>)` to stdout and exits
0 — handled in the arg loop like `--help`. Examples:
`sqdist 0.2.0 (a1b2c3d)` or `sqdist 0.2.0 (unknown)`.

`build.rs` must be added to the crate `include` list in `Cargo.toml` so
crates.io packaging includes it; the `(unknown)` fallback keeps that build
working without git.

## Feature 3 — Field explanations in help

`print_usage` gains a "FIELD MEANINGS" section, one line per field:

- `levenshtein` — minimum single-character insert/delete/substitute edits.
- `damerau` — like levenshtein but counts an adjacent transposition as one edit.
- `homoglyph_damerau` — Damerau distance where a confusable substitution costs
  `--hogl-weight` (default 0.1) instead of 1.
- `skeleton_damerau` — Damerau distance after reducing both strings to their
  UTS#39 skeletons; ~0 when visually identical, including multi-char confusables.
- `normalized` — `homoglyph_damerau / max(len_a, len_b)`, a 0–1 ranking score.
- `skeleton_normalized` — `skeleton_damerau / max(skeleton_len_a, skeleton_len_b)`.
- `confusable_only` — true when the strings differ but share an identical
  skeleton (a pure homoglyph spoof).

## Feature 4 — `--fields <comma-list>`

`--fields damerau,confusable_only` restricts which score fields appear in output.

- Applies to **all modes** (single-pair human, `-j` JSON, `--stdin`/`--list` JSONL).
- The two identifier keys are **always** emitted in JSON/JSONL (`a`/`b`, or
  `input`/`match`) — they are not score fields and not subject to `--fields`.
- Output preserves the **canonical field order**, not the order the user typed.
- Valid field names: `levenshtein, damerau, homoglyph_damerau, skeleton_damerau,
  normalized, skeleton_normalized, confusable_only`. An unknown name → error to
  stderr listing valid names, exit 2.
- `-t` and `--metric` operate on the **full internal `Scores`** regardless of
  `--fields`, so display filtering never affects thresholding/sorting.
- The single-pair verdict (Feature 5) still prints — it is a verdict, not a
  field, and is computed from the full scores.

Human single-pair example:
```
$ sqdist --fields damerau,confusable_only GOOGLE GO0GLE
damerau              1
confusable_only      true

[LIKELY SPOOF] The strings differ by 1 edit, and that difference is a
homoglyph (visually confusable character). High likelihood of an attempt
to confuse.
```

JSON example:
```
$ sqdist -j --fields damerau,confusable_only GOOGLE GO0GLE
{"a":"GOOGLE","b":"GO0GLE","damerau":1,"confusable_only":true}
```

## Feature 5 — Interpretation verdict (single-pair human output only)

After the field table and a blank line, print `[CATEGORY] explanation`. Appears
**only** in single-pair, non-JSON output. NOT in `-j` JSON (stays pure JSON) and
NOT in batch modes (would break JSONL / add per-line noise).

Three categories:

- **`[IDENTICAL]`** — `a == b`. "The strings are identical."
- **`[LIKELY SPOOF]`** — homoglyphs are the majority contributor to the
  difference. True when:
  `confusable_only == true`
  **OR** (`homoglyph_share > 0.5` **AND** `max(len_a, len_b) >= 3`
  **AND** `len_diff_ratio <= len_tolerance`)
  where:
  - `homoglyph_share = (damerau - skeleton_damerau) / damerau` (0 if damerau == 0)
  - `len_diff_ratio = |len_a - len_b| / max(len_a, len_b)` (0 if both 0)
  - `len_tolerance` defaults to 0.25, overridable via `--len-tolerance <F>`.
  Sentence cites the edit count and that the difference is (mostly) homoglyphs;
  states a high likelihood of an attempt to confuse.
- **`[LIKELY BENIGN]`** — everything else. The sentence adapts on a fixed
  boundary:
  - `damerau <= 2` → "...likely a typo." (optionally noting any minor homoglyph
    involvement when `skeleton_damerau < damerau`).
  - `damerau >= 3` → "...the strings appear unrelated."

`len` here means character count (`chars().count()`), consistent with how the
distance functions count.

The verdict is produced by a pure function:
`verdict(scores: &Scores, len_a: usize, len_b: usize, len_tolerance: f64) -> (Category, String)`
where `Category` is an enum (`Identical | LikelySpoof | LikelyBenign`) used for
the `[TAG]`, and the `String` is the explanation sentence built from the field
values. Unit-tested directly.

## Cross-cutting

### New flags
- `-v, --version` — print version + SHA, exit 0.
- `--fields <comma-list>` — restrict displayed fields.
- `--len-tolerance <F>` — length-difference threshold for the spoof verdict
  (default 0.25). Parsed like `--threshold` (f64).

### Opts additions
`Opts` gains: `fields: Option<Vec<Field>>` (None = all), `len_tolerance: f64`
(default 0.25). A `Field` enum or a fixed canonical-order list backs both the
parsing/validation and the ordered emission.

### Testability
Pure, unit-tested helpers:
- `verdict(&Scores, usize, usize, f64) -> (Category, String)`
- field parsing/validation: `parse_fields(&str) -> Result<Vec<Field>, String>`
- ordered field emission used by both `result_json` and `emit` (they take the
  selected-fields set and honor canonical order).

`main()` stays a thin I/O wrapper. Existing 22 tests remain green; add tests for
the verdict categories (identical, single-char spoof, multi-char spoof,
benign typo, unrelated, length-tolerance boundary), field parsing (valid,
invalid, ordering), and the batch exit-code behavior.

### Files
- `Cargo.toml` — version 0.2.0; add `build.rs` and `/build.rs` to `include`.
- `build.rs` — new; git SHA capture with `unknown` fallback.
- `src/main.rs` — flags, Opts, verdict, field filtering, exit codes, help text.
- `README.md`, `CLAUDE.md` — document new flags, version, field filtering, verdict.

## Out of scope
- No verdict in JSON or batch output (single-pair human only).
- No user-defined field ordering (canonical order always).
- No new runtime dependencies (build.rs uses std `Command` to call git).
- No changes to the distance algorithms or the confusables data.
